# LangGraph 并行节点

## 概念

并行节点是 LangGraph 中用于实现任务并行执行的核心组件。在复杂的 AI 工作流中，经常需要同时执行多个不相互依赖的任务，例如同时对一段文本进行摘要、情感分析和关键词提取。并行节点允许将这些任务定义为图中的独立分支，并在同一时间点并发运行，从而显著降低整体处理延迟。与传统的串行管道相比，并行节点能够充分利用计算资源，提升吞吐量。

在 LangGraph 的图结构中，并行节点通常表现为从一个状态节点分叉出的多个子节点或子图。每个分支具有独立的处理逻辑，但它们共享相同的输入上下文。最终，这些分支的输出可以通过合并节点（如 `collect` 节点）汇聚到一起，供后续节点使用。

## 原理

LangGraph 的并行执行机制基于有向无环图（DAG）的调度算法。当图执行到达一个并行节点时，引擎会分析所有出边，识别出那些没有数据依赖关系的分支。然后，LangGraph 使用线程池或异步任务（取决于运行环境）同时启动这些分支的执行。每个分支运行时拥有独立的执行上下文，包括状态副本和运行时变量，以避免共享状态带来的竞态问题。

关键的执行步骤包括：
1. **分支定义**：在图上通过 `add_node` 或 `add_conditional_edges` 创建多个出边，每个出边指向一个子节点。
2. **任务调度**：LangGraph 的调度器收集所有可并行执行的任务，并将其提交给并发执行器。
3. **结果收集**：所有并行分支执行完毕后，调度器将结果按照定义的合并策略（如 `list`、`dict` 或自定义函数）聚合，然后传递给下游节点。

LangGraph 还支持动态并行，即根据运行时数据决定并行分支的数量和内容，这通过 `add_parallel_executor` 或自定义逻辑实现。

## 实践案例

### 架构流程

假设我们需要处理一批用户反馈文本，要求同时进行**情感分类**、**语言检测**和**关键词提取**。架构如下：
- 输入节点：接收用户反馈文本。
- 并行节点：创建一个拆分点，分别连接到三个处理节点：情感分析节点、语言检测节点、关键词提取节点。每个节点使用不同的预训练模型或 API。
- 合并节点：三个节点的输出结构不同，合并节点将它们整合为一个统一的 JSON 对象。
- 输出节点：将合并后的结果写出。

### 关键参数

- `parallelism`: 控制最大并行分支数，默认为 4。可根据 CPU 核心数或 API 配额调整。
- `timeout`: 每个分支的超时时间，单位秒。超时后分支将被标记为失败，并触发异常处理。
- `collect_strategy`: 定义如何合并分支结果，可选 `list`、`dict`、`callable`。
- `retry_count`: 分支执行失败时的重试次数，默认 0。
- `allow_partial`: 是否允许部分分支失败时仍继续整体流程，默认为 False 表示任何分支失败则流程终止。

### 异常处理

- 若某个分支抛出异常（如模型调用失败），根据 `allow_partial` 设置决定行为：
  - `allow_partial=False`: 整个并行节点失败，图执行中断，并向上抛出异常。
  - `allow_partial=True`: 失败分支的结果被设置为 `None` 或默认值，其他分支正常执行。合并节点需要能处理缺失字段。
- 可在每个分支内使用 try-catch 进行本地错误捕获，并返回错误标志。
- 超时异常视为失败，同样受上述规则控制。

### 监控指标

- **分支执行时间**：每个分支从开始到结束的耗时。
- **并行节点总耗时**：从调度到所有分支完成的时间。
- **并发数**：实际同时运行的分支数量。
- **失败率**：失败分支数 / 总分支数。
- **等待时间**：因资源限制导致分支等待调度的时长。

这些指标可以通过 LangGraph 内置的钩子（hooks）或日志导出到监控系统。

### 方案取舍

- **并行 vs 串行**：并行节点可大幅缩短总执行时间，但增加资源消耗和复杂度。若分支数量少且执行时间差异大，并行更优；若分支有隐式依赖或需要严格顺序，应使用串行。
- **静态并行 vs 动态并行**：静态并行适合分支数量和逻辑固定的场景；动态并行适合分支数量随输入变化的场景，但实现更复杂。
- **线程安全**：并行分支不应共享可变状态，需通过传入副本或使用不可变数据结构保证安全。
- **成本控制**：若分支调用付费 API，并行会增加瞬时并发请求，可能突破 API 速率限制。需要利用 `timeout` 和 `retry` 配合限流。
