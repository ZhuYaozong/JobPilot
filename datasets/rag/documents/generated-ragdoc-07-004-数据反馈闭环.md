# 数据反馈闭环

## 概念

数据反馈闭环是指在AI系统中，通过收集模型在部署后产生的真实数据，将其反馈至训练或微调流程，从而持续优化模型性能的机制。该闭环强调数据、模型、应用之间的循环流动，使模型能够适应环境变化和用户需求演进。核心要素包括数据采集、标注/筛选、版本管理、评估和再训练。与传统离线训练不同，反馈闭环要求自动化、低延迟且可观测，属于MLOps（机器学习运维）的关键组成部分。

## 原理

数据反馈闭环建立在持续学习（Continual Learning）与在线评估（Online Evaluation）两大理论基础之上。其工作流程如下：

1. **数据采集**：从线上服务中捕获模型输入、输出以及用户反馈（如点击、评分、纠错行为）。采集需遵循隐私合规且保证样本代表性，避免分布偏移。
2. **数据筛选与标注**：通过规则或模型初步过滤低质量数据（如异常值、重复项），再结合人工或半自动标注生成高质量标注集。关键参数包括采样率（如仅采集10%的边缘案例）、标注置信度阈值（如0.95）以及人机协同的比例。
3. **数据版本化**：将新数据整理为数据集版本，记录时间戳、分布统计和元信息，便于回滚和审计。
4. **评估与触发**：监控模型在生产环境中的性能指标（如准确率、延迟、异常率）。当指标下降超过阈值（如准确率降低2%）或数据分布变化超过漂移检测阈值（如PSI>0.2），触发重新训练。
5. **重训练与部署**：利用新旧数据混合重新训练模型，通过A/B测试验证改进效果，再将新模型部署上线。

闭环周期取决于业务节奏，常见为周级或月级。异常处理包括：当数据采集延迟或标注质量波动时，暂缓触发；若重训练后指标未改善，则回滚至上一版本并告警。监控指标涵盖数据流入速率（如每小时新增样本数）、标注完成率、模型漂移程度、重训练耗时、以及线上AB测试胜出率。方案取舍：自动化闭环可提升适应性但成本高，适合流量大、变化快的场景（如推荐系统）；人工审核闭环更可靠但速度慢，适合高安全场景（如医疗决策）。平衡点在于采用混合策略：规则自动过滤+人工抽检。

## 实践案例

以某电商搜索排序模型为例构建数据反馈闭环。

**架构流程**：
- 线上服务 → 日志采集系统（Fluentd） → 消息队列（Kafka） → 数据清洗模块（Spark Streaming） → 特征存储（Feast） → 样本池（HDFS） → 离线训练（PyTorch） → 模型注册中心（MLflow） → A/B测试平台 → 生产环境。
- 用户点击、加购、下单行为实时写入Kafka，每5分钟聚合一次。清洗规则移除请求次数＞100/秒的异常用户，以及出现缺失特征（＞50%）的样本。每天凌晨执行标注：用户明确行为（如点击）视作正样本，曝光未点击为负样本，但需加入时间衰减（权重=0.9^天数）。
- 漂移检测每月运行，采用PSI（群体稳定性指数）对比线上特征分布与训练数据分布，阈值0.25。当PSI>0.25或模型AUC下降≥0.03时，自动启动重训练。

**关键参数**：
- 采样率：全量采集点击行为，只采集10%的曝光未点击（避免类不平衡）。
- 标注质量：人工抽检5%的自动标注，要求一致率≥95%。
- 训练周期：周级重训练，增量更新Embedding层，全量更新顶层网络。
- 部署策略：金丝雀发布，新模型先承接5%流量，观察3天无异常后全量。

**异常处理**：
- 队列积压：若Kafka延迟＞30分钟，关闭数据采集的无效过滤环节，优先保证关键特征入库。
- 标注失败：自动标注模型失效时切换至人工标注，并降低重训练触发阈值（AUC下降0.01即触发）。
- 部署回滚：当新模型导致线上点击率下降超过5%或P99延迟增加20%，自动回滚至上一版本并发送告警。

**监控指标**：
- 数据流健康：每小时新增样本数（期望≥100万），异常样本比例（<1%），特征缺失率（<5%）。
- 模型性能：线上AUC、NDCG@10、点击率。每日报表，异常时邮件通知。
- 闭环效率：从新数据产生到模型部署的平均用时（目标＜7天），重训练执行成功率（≥99%）。
- 稳定性：特征分布PSI，模型预测均值偏移（期望每日漂移＜0.5%）。

**方案取舍**：
- 全自动化VS人机协同：因搜索场景对实时性敏感，采用自动化采集与标注，但保留人工抽检与异常干预。
- 增量训练VS全量训练：由于数据量大且趋势变化稳定，选择每周全量训练一次，日常增量更新浅层特征。
- 在线学习VS离线闭环：不采用在线学习以避免模型遗忘，而是在离线闭环中引入经验回放（Replay Buffer）缓解灾难性遗忘。
- 复杂度与效果平衡：优先保证数据质量，因此对低置信度样本（<0.6）进行人工确认，而非盲目增加数量。

该闭环上线后，模型AUC从0.78提升至0.83，点击率增长12%，且回滚次数从每月3次降至1次，运维成本可控。
