# 文档解析与清洗

## 概念
文档解析与清洗是RAG系统中的关键预处理环节。文档解析负责将非结构化文档（如PDF、HTML、Word）转换为结构化文本，而清洗则去除噪声、统一格式、修复错误。这两个步骤直接影响后续检索的质量和生成答案的准确性。常见挑战包括复杂版式（表格、多栏）、OCR错误、特殊符号以及编码问题。

## 原理
文档解析主要依赖规则引擎和机器学习模型。对于PDF，常用工具（如PyMuPDF、pdfplumber）提取文本和布局信息；对于扫描件，结合OCR（如Tesseract）识别文字。清洗阶段采用正则表达式、字符串操作和NLP方法：去除多余空白、标准化Unicode、纠正常见OCR错误（如“0”与“O”混淆）、过滤广告/页眉页脚。为适应RAG，还需分块（chunking）策略，如按段落、句子或固定长度分割，并保留元数据（页码、标题层级）。

## 实践案例
### 架构流程
假设处理一个含有表格和图片的PDF报告。流程如下：
1. 输入PDF → 解析器（PyMuPDF提取文本+布局）→ 若发现图片区域，调用OCR引擎（Tesseract）识别文字。
2. 解析后文本 → 清洗模块：去除页眉页脚（基于位置规则）、合并断行（行尾连字符）、标准化日期格式。
3. 清洗后文本 → 分块器：按Markdown标题划分，若无则按500字符滑动窗口，重叠50字符。
4. 输出：每个块带有id、内容、元数据（来源页码、标题路径）。

### 关键参数
- 分块大小：500字符（经验值），过大导致检索不精确，过小丢失上下文。
- 重叠：50字符，保证边界句子不被截断。
- OCR置信度阈值：0.8，低于此重识别或标记为低质量。
- 清洗正则：例如`\s+`替换为单个空格，移除`[\r\n]{3,}`。

### 异常处理
- 不可读PDF（加密或损坏）：记录错误日志，跳过该文档或返回空列表。
- OCR失败：若图片区域大面积模糊，降级为占位符“[image]”，并标记需人工介入。
- 编码异常：检测到非UTF-8字符，尝试用`chardet`识别编码，转换失败则丢弃该字符。
- 分块超长：对超过2000字符的块，强制按句子分句再合并到合理范围。

### 监控指标
- 解析成功率：成功解析文档数/总文档数，目标>95%。
- 清洗后字符压缩率：清洗后字符数/原始字符数，反映噪声去除程度，正常0.6-0.9。
- OCR召回率：正确识别字符数/图片中实际字符数（抽样评估），目标>80%。
- 分块平均长度：接近设定值500，标准差<100。
- 异常频率：每小时记录错误次数，触发告警。

### 方案取舍
- 规则 vs 模型：规则清洗速度快、可解释，但对多样式泛化差；ML模型（如版面分析）更准但计算开销大。本方案以规则为主，仅OCR环节用模型。
- 分块策略：滑动窗口固定长度简单，但会切断段落；语义分块（按标题或句子）保留结构，但可能产生大小不均。选择滑动窗口+元数据标记，平衡简单与效果。
- 解析工具：PyMuPDF速度快，但复杂表格可能错位；pdfplumber表格提取好，但解析大文件慢。按场景混用：纯文本用PyMuPDF，表格密集用pdfplumber。
