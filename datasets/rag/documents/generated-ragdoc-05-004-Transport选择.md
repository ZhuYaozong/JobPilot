# MCP Transport选择指南

## 概念

MCP（Model Context Protocol）是一种开放协议，用于连接AI模型与外部工具、数据源。Transport层定义了客户端与服务器之间通信的具体方式，负责消息的序列化、传输和路由。常见的Transport实现包括stdio（标准输入/输出）和HTTP（含SSE流）两种。选择合适的Transport直接影响系统的延迟、吞吐量、部署复杂度以及安全性。

## 原理

Transport层在MCP协议栈中处于最底层，负责将上层消息（如请求、通知、结果）编码为传输格式并通过网络或进程间通道发送。stdio Transport利用子进程的标准流进行双向通信，适合本地嵌入场景，延迟低但难以跨网络。HTTP Transport基于RESTful风格，通常结合Server-Sent Events实现流式响应，适合服务化部署，可伸缩性强但引入HTTP开销。MCP规范定义了每种Transport的端点、认证、心跳等细节。选择时需评估环境约束：本地或远程、同步或异步需求、防火墙策略、负载均衡支持等。

## 实践案例

假设需要为一个AI应用集成文件系统访问工具，要求低延迟且部署在同一主机。选择stdio Transport。

### 架构流程

1. AI应用启动一个子进程运行MCP服务器。
2. 应用通过stdin发送JSON-RPC消息（如`{"jsonrpc":"2.0","method":"tools/call","params":{}}`）。
3. 服务器通过stdout返回结果，stderr用于日志。
4. 应用读取stdout并解析响应。
5. 心跳：服务器定期向stdout发送空行维持连接。

### 关键参数

- `command`: 服务器可执行文件路径（如`/usr/bin/mcp-filesystem`）。
- `args`: 启动参数数组。
- `env`: 环境变量覆盖（如`API_KEY`）。
- `cwd`: 工作目录。
- `timeout`: 默认30000ms，超过则关闭进程。

### 异常处理

- 进程异常退出：捕获`exit`事件，记录错误码，尝试重启（最多3次，间隔1s）。
- 消息超时：设置读取超时，超时后发送`cancel`方法并关闭通道。
- 协议解析错误：记录无效消息，忽略并继续。

### 监控指标

- 消息传输延迟（ms）：从写入到读取的耗时。
- 消息吞吐量（msg/s）：每秒处理的请求数。
- 进程重启次数：超过阈值报警。
- 内存占用：监控子进程RSS，超出限制时重启。

### 方案取舍

| 方面 | stdio | HTTP |
|------|-------|------|
| 延迟 | 1-5ms | 10-50ms |
| 跨网能力 | 弱 | 强 |
| 部署复杂度 | 低 | 高（需Web服务器） |
| 安全性 | 进程隔离 | 支持TLS、认证 |
| 负载均衡 | 无 | 支持 |

当前案例选择stdio，因本地低延迟需求优先，且无跨网或高可用要求。
