# 工具契约：Agent与外部工具的协作规范

## 概念

工具契约（Tool Contract）是 Agent 与外部工具之间的一套明确定义的交互协议。它规定了工具的功能、输入输出格式、错误处理方式以及副作用，确保 Agent 能够可靠地调用工具并正确解析结果。工具契约类似于 API 文档，但更强调 Agent 自动调用时的健壮性和可验证性。

## 原理

工具契约的设计遵循“契约优先”原则：Agent 开发者和工具提供者共同商定一个不可变的接口规范。该规范包含：
- **标识与元数据**：工具名称、版本号、描述。
- **输入参数**：每个参数的类型、默认值、约束条件（如必填、取值范围）。
- **输出格式**：成功响应的结构，通常为 JSON 格式。
- **错误响应**：错误码、错误消息、重试建议。
- **副作用**：工具执行可能产生的副作用（如写入数据库、发送网络请求），Agent 需据此决定调用时机。

Agent 在执行时，先读取契约中的参数约束对输入进行校验，调用工具后根据输出类型解析结果，遇到错误时根据契约中的错误码选择重试或降级。

## 实践案例

### 场景：天气查询工具
Agent 需要调用外部天气 API 获取指定城市的当前温度。工具契约定义如下。

#### 架构流程
1. Agent 收到用户请求“北京今天多少度？”。
2. Agent 识别意图为“查询天气”，匹配工具“GetWeather”。
3. Agent 加载工具契约，校验参数“city”必填且为字符串。
4. Agent 调用 GetWeather（参数：city="北京"）。
5. 工具向天气 API 发送 HTTP GET 请求。
6. 工具接收响应，按契约格式返回 JSON。
7. Agent 解析输出，提取温度字段并生成回复。

#### 关键参数
- `city`：字符串，必填，长度 1-100，支持中文。
- `api_key`：字符串，必填，由工具内部配置，Agent 无需感知。
- `units`：可选，枚举值（"celsius", "fahrenheit"），默认 "celsius"。

#### 异常处理
- **网络超时**：契约规定超时时间为 5 秒，超时后返回错误码 `TIMEOUT`。Agent 捕获后重试最多 2 次，间隔 1 秒。
- **无效城市**：工具返回错误码 `INVALID_CITY`。Agent 提示用户重新输入有效城市名。
- **API 配额耗尽**：错误码 `QUOTA_EXCEEDED`。Agent 记录日志并降级为缓存数据（若有）或返回“暂时无法获取”。

#### 监控指标
- **调用成功率**：成功响应数 / 总调用数，目标 > 99%。
- **平均响应延迟**：从 Agent 发起调用到收到响应的时间，目标 < 2 秒。
- **错误分布**：按错误码统计次数，用于发现工具或 API 故障。
- **参数校验失败率**：Agent 内部校验未通过的比例，反映用户输入质量。

#### 方案取舍
- **同步 vs 异步**：对于天气这类实时性要求高的场景采用同步调用；对于长时间任务（如文件处理）采用异步轮询。本案例选择同步，简单直接，但需控制超时。
- **缓存策略**：为降低 API 调用和提升响应速度，可引入 TTL 为 10 分钟的本地缓存。缓存命中时直接返回，跳过工具调用。代价是牺牲轻微的数据新鲜度。
- **重试策略**：采用指数退避（1s, 2s, 4s）最多 3 次，平衡负载与成功率。对于非幂等工具（如下单）需谨慎使用重试。
