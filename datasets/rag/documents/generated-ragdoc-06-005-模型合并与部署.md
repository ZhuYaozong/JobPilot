# LoRA/SFT 模型合并与部署实践

## 概念

LoRA（Low-Rank Adaptation）是一种高效的微调方法，通过在预训练模型的权重矩阵上添加低秩可训练矩阵，实现参数高效的领域适配。SFT（Supervised Fine-Tuning）则是指使用监督数据对模型进行全参数或部分参数微调。模型合并是指将微调得到的 LoRA 权重与基础模型权重融合，生成单一完整模型，便于部署和推理。部署则将合并后的模型加载到推理环境，提供 API 或直接使用。

## 原理

LoRA 的核心思想是假设权重更新矩阵 ΔW 具有低秩性，将其分解为两个低秩矩阵 A 和 B 的乘积：ΔW = BA，其中 B ∈ ℝ^{d×r}，A ∈ ℝ^{r×d}，r 远小于原始维度 d。训练时冻结预训练权重 W_0，仅优化 A 和 B。推理时需将 ΔW 加回 W_0，即 W = W_0 + α * BA。模型合并过程即计算并存储融合后的权重矩阵，消除对额外 LoRA 参数的依赖。

## 实践案例

### 架构流程

1. **基础模型准备**：加载预训练基座模型（如 LLaMA、ChatGLM），并确保其权重为 FP16 格式以节省显存。
2. **LoRA 权重导出**：从 SFT 训练检查点中提取 LoRA 权重（adapter_model.bin），包含 A 和 B 矩阵以及缩放系数 alpha。
3. **合并脚本编写**：使用 HuggingFace PEFT 库的 `merge_and_unload` 方法或手动实现合并逻辑：遍历所有 LoRA 模块，计算 ΔW = alpha * (B @ A)，累加到原始权重对应位置。
4. **模型保存**：合并后调用 `model.save_pretrained(save_dir)` 保存完整模型，并复制 tokenizer 文件。
5. **部署推理**：使用 vLLM、TGI 或 FastAPI 加载完整模型，配置批量推理参数。

### 关键参数

- **r（秩）**：控制低秩矩阵维度，典型值 8、16、32。值越大，微调能力越强但参数量增加。实践中常设为 8。
- **alpha（缩放系数）**：控制合并时 LoRA 权重的贡献，通常设为 r 的倍数（如 16 或 32）。
- **target_modules**：指定应用 LoRA 的层，如 q_proj、v_proj。不同任务需调整。
- **保存精度**：合并时建议保持 FP16，避免精度损失。若需量化可后续使用 GPTQ 或 AWQ。

### 异常处理

- **显存溢出**：合并期间需额外存储完整权重，若 GPU 显存不足，可使用 CPU 卸载或分块合并。例如将模型移至 CPU 合并后再转回 GPU。
- **键名不匹配**：LoRA 检查点与基础模型层名必须对应。若训练时模块命名不同，需手动映射键名。
- **权重冲突**：若多次 LoRA 权重叠加，需决定是否平均或按优先级加权。常见做法是训练一个综合 LoRA。
- **推理速度慢**：合并后模型大小增大，可考虑量化或使用投机性推理。

### 监控指标

- **合并后模型困惑度（PPL）**：与原始模型对比，差异应小于 5%，否则检查合并逻辑。
- **推理延迟**：合并前后单次推理时间，应接近（因无额外计算）。
- **峰值显存**：合并与推理时的显存占用，避免 OOM。
- **下游任务指标**：如果用于分类或生成，对比微调前的基础模型效果，LoRA 应提升。

### 方案取舍

- **在线合并 vs 离线合并**：在线合并在训练后立即合并，节省存储；离线合并允许分开发布 LoRA 权重和基座，便于模块化。离线合并可节省磁盘空间（仅存 LoRA），但推理时需每次合并。生产环境常离线合并一次。
- **PEFT 合并方法 vs 自定义**：PEFT 的 `merge_and_unload` 方便但需适配库版本；自定义合并更灵活，可控制精度。建议优先使用 PEFT 方法，遇到兼容性问题时手动实现。
- **合并后量化**：若对推理速度要求高，可合并后量化至 INT4 或 INT8，但可能损失 1-2% 准确率。需评估业务容忍度。
