# Agent 短期与长期记忆机制

## 概念

Agent 的记忆模块分为短期记忆和长期记忆。短期记忆是 Agent 在与用户交互过程中临时存储的上下文信息，通常由对话历史、当前任务状态和中间推理结果组成。它决定了 Agent 在单个会话中的连贯性。长期记忆则是 Agent 在多次会话或长时间运行中持久化存储的知识和经验，包括用户偏好、学习到的规则、知识库条目以及之前的解决方案。长期记忆使 Agent 能够跨会话保持一致性，并在未来任务中复用历史信息。二者相互协作：短期记忆提供即时工作空间，长期记忆为短期记忆提供背景知识和历史参考。

## 原理

短期记忆通常实现为一个有限容量的缓存（如滑动窗口或优先级队列），存储最近 N 轮对话或最近 K 个 token。当缓存满时，采用遗忘策略（如时间戳淘汰或重要性评分淘汰）移除旧内容。长期记忆则依赖外部持久化存储，如向量数据库或关系型数据库。Agent 在执行任务时，先查询长期记忆获取相关背景（通过语义搜索或关键词匹配），将结果注入到短期记忆中作为上下文。同时，Agent 会定期或在关键决策点将短期记忆中有价值的信息（如用户确认的偏好、成功策略）写入长期记忆。写入前可能经过摘要、压缩或去重处理。短期记忆和长期记忆的协同使得 Agent 既能快速响应当前交互，又能持续学习并改进。

## 实践案例

假设构建一个帮助用户安排日程的 Agent。

### 架构流程

1. 用户输入“每周一上午 9 点开会”，Agent 将此信息存入短期记忆。
2. Agent 查询长期记忆（向量数据库）中该用户的日程模式，发现用户之前曾在周一上午 10 点有课程，于是返回冲突警告。
3. Agent 使用短期记忆中的当前请求和长期记忆中的历史冲突案例，生成建议“是否调整到周二下午？”。
4. 用户确认后，Agent 将新日程写入短期记忆，并在会话结束时将更新的偏好（周一上午繁忙）写入长期记忆。

### 关键参数

- **短期记忆窗口大小**：设定为 1000 个 token（约 500 个中文词），超过则按时间戳移除最早内容。
- **长期记忆检索 top-k**：5 条最相似的历史记录。
- **写入长期记忆触发条件**：用户明确确认或任务成功完成。
- **记忆压缩阈值**：当短期记忆中有超过 3 条相似条目时，自动摘要合并再写入长期记忆。

### 异常处理

- **短期记忆溢出**：当输入过长导致窗口不足时，Agent 提示用户精简请求或自动截断最早内容，并记录警告日志。
- **长期记忆检索失败**：向量数据库超时或无匹配，Agent 退化为仅使用短期记忆，同时重试一次。若持续失败，在用户界面显示“网络连接不稳定”。
- **写入冲突**：新信息与长期记忆中现有信息矛盾（如用户说“改为周二”，但长期记忆仍认为周一有空），Agent 会再次确认用户意图后覆盖旧记录。

### 监控指标

- **短期记忆命中率**：Agent 在推理时实际使用的短期记忆条目占可用条目的比例。目标 >80%。
- **长期记忆检索延迟**：从查询到返回结果的时间，P99 <200ms。
- **记忆写入成功率**：成功写入长期记忆的次数 / 尝试写入次数，目标 >99%。
- **用户满意度评分**：每次会话结束时用户打分，1-5 分，目标 >4.2。

### 方案取舍

- **短期记忆存储策略**：采用滑动窗口 vs 重要性评分。滑动窗口实现简单但可能丢弃重要旧信息。此处选择滑动窗口，因场景对话轮次短，重要性评分增加复杂度收益不明显。
- **长期记忆索引**：向量索引 vs 键值索引。向量索引支持语义搜索，适合模糊记忆；键值索引查询速度快但只能精确匹配。优先向量索引，因为用户的日程描述可能变化。
- **写入时机**：实时写入 vs 批量写入。实时写入延迟低但频繁写库；批量写入减少压力但可能丢失最近状态。此处选择实时写入，因为用户偏好更新需立即生效。
