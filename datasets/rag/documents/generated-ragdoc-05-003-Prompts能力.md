# MCP Prompts能力详解

## 概念

MCP（Model Context Protocol）中的Prompts能力是指服务器端定义的可复用提示模板集合，客户端可通过标准协议动态获取并执行这些提示。与普通硬编码提示不同，MCP Prompts支持参数化、版本管理和热更新，允许AI应用在不修改客户端代码的情况下调整LLM的行为。每个Prompt包含唯一的ID、模板字符串（支持占位符）以及可选的参数描述。客户端在需要生成对话时，向服务器请求特定的Prompt并传入实际参数，服务器则返回渲染后的完整提示文本。这种机制实现了提示逻辑的集中管理和跨应用共享，特别适合多模型、多场景的复杂系统。

## 原理

MCP Prompts遵循客户端-服务器架构。服务器端通过注册表管理一组Prompt定义，每个定义包含：
- id：唯一标识符
- template：Mustache或F-string风格的模板，包含{placeholder}等占位符
- arguments：描述每个参数的名称、类型、是否必需以及说明。

客户端通过`prompts/list` RPC方法获取所有可用Prompt的元数据（不含模板内容），再通过`prompts/get`方法传入参数值，获取渲染后的提示字符串。服务器收到请求后，验证参数完整性，使用模板引擎填充占位符，若参数缺失则返回错误。此外，协议支持动态参数，即参数值可由服务器动态生成（如当前时间、随机数）。

流程如下：
1. 客户端初始化时调用`prompts/list`获取Prompt目录。
2. 当需要生成特定提示时，客户端选择目标Prompt ID，构造参数对象。
3. 调用`prompts/get`发送请求。
4. 服务器校验参数，进行模板渲染，返回结果。
5. 客户端将渲染后的文本作为系统提示或用户消息发送给LLM。

关键设计原则：
- 无状态：每个`prompts/get`请求独立渲染，不依赖上下文。
- 可缓存：`prompts/list`结果可缓存至TTL过期，减少请求。
- 扩展性：服务器可动态增删Prompt，客户端无需重启。

## 实践案例

**场景**：构建一个代码审查助手，使用MCP Prompts定义不同审查维度的提示。

### 架构流程
- 组件：前端Web App（客户端）、MCP服务器（Node.js）、LLM API（如GPT-4）。
- 流程：
  1. 客户端启动时调用`list`获取三个Prompt ID："security_review"、"style_review"、"perf_review"。
  2. 用户提交代码片段后，前端选择“安全审查”按钮。
  3. 客户端调用`get`，参数包括{code: "用户代码"}。
  4. 服务器使用"security_review"模板渲染成完整提示，返回。
  5. 客户端将提示发送给LLM，并将回复展示给用户。

### 关键参数
- `prompts/get`请求参数：
  - `id`（必填）：如"security_review"。
  - `arguments`：对象，如{"code": "..."}。
- 模板示例："请审查以下代码的安全漏洞：\n\n{code}\n\n重点关注SQL注入、XSS、认证绕过。"
- 参数定义：`code`为必需字符串，最大10000字符。

### 异常处理
- 参数缺失：服务器返回错误码-32602，消息"Missing required argument: code"。客户端应提示用户重新提交。
- 无效Prompt ID：返回-32601，客户端应回退到默认提示或刷新列表。
- 参数过长：返回-32000，客户端需截断代码并警告。
- LLM调用失败：客户端捕获LLM错误，提示用户稍后重试，并可记录失败日志。

### 监控指标
- `prompts/list`调用频率：每分钟次数，缓存命中率。
- `prompts/get`调用次数、平均响应时间（服务器渲染耗时）、参数大小分布。
- 错误率：按错误码分类（参数缺失、ID无效等）。
- LLM调用成功率、平均Token消耗。
- 告警阈值：`get`错误率>5%触发报警。

### 方案取舍
- **使用MCP Prompts** vs **直接在前端硬编码**：MCP方案可实现提示热更新、集中管理，但增加一次网络往返延迟（通常<10ms）。适合提示频繁变化或多客户端共享的场景。
- **参数化模板** vs **多个独立Prompt**：参数化减少Prompt数量，但模板复杂度增加。当参数组合少且固定时，独立Prompt更清晰；当参数多时，参数化更灵活。
- **服务器渲染** vs **客户端渲染**：服务器渲染可保证一致性，但增加服务器CPU开销。客户端渲染可将模板分发给客户端，但需更复杂的版本控制。MCP选择服务器渲染以简化客户端。
