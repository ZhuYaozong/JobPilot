# Prompt设计：原则、原理与实践案例

## 概念

Prompt（提示）是用户向大语言模型（LLM）提供的输入文本，用于引导模型生成期望的输出。Prompt设计是指通过构造特定的文本格式、上下文和指令，以优化模型的行为与结果。良好的Prompt能显著提升模型回答的准确性、相关性和可控性，是LLM应用落地的核心技术之一。

Prompt通常包含角色设定、任务描述、输入数据、输出格式要求以及示例（few-shot）等元素。其设计原则包括明确性、具体性、结构化及迭代优化。

## 原理

LLM基于自回归或编码器-解码器架构，通过大规模预训练学习到丰富的语言知识和模式。当给定一个Prompt时，模型会根据已学习的概率分布，自回归地生成后续token。Prompt的本质是提供条件分布中的“条件”，引导模型从高概率区域采样。

关键原理包括：
- **上下文学习**：模型能够从Prompt中的示例中提取任务模式，无需微调即可适应新任务。
- **指令遵循**：通过清晰的指令，模型可以执行指定行为，如“总结”、“翻译”或“分类”。
- **角色提示**：赋予模型特定角色（如“专家”或“助手”），可激活相应知识领域的表示。
- **思维链**：通过要求模型逐步推理，可提升复杂问题的解决能力。

Prompt的效果受限于模型的知识边界、上下文窗口长度以及prompt的清晰程度。设计时需避免模糊、冲突或过于开放的指令。

## 实践案例

### 场景：客户评论情感分析

目标：基于用户评论，判断情感极性（正面、负面、中性），并输出结构化结果。

#### 架构流程
1. 输入：原始评论文本（如“电池续航不错，但屏幕太暗。”）
2. Prompt模板：
   ```
   你是一个情感分析专家。请判断以下评论的情感极性（正面、负面或中性），并以JSON格式输出。
   评论：{评论}
   输出：
   ```
3. 模型推理：LLM根据prompt生成输出。
4. 解析：提取JSON字段，验证格式。
5. 后处理：若输出不符合预期，触发重试或默认处理。

#### 关键参数
- **模型**：GPT-3.5-turbo（温度0，top_p 0.1，以保证输出确定性）
- **上下文窗口**：最大输入token 4096，限制评论长度。
- **示例数量**：0-shot（无示例），若效果差则增加2-3个few-shot示例。
- **角色描述**：使用“情感分析专家”角色。

#### 异常处理
- **输出格式错误**：若JSON解析失败，重试最多2次，每次附加提示“请严格输出合法的JSON对象，包含key: sentiment”。
- **情感模糊**：若输出包含“混合”或不确定，强制归类为“中性”。
- **内容违规**：若模型拒绝回答，返回默认类别“中性”。
- **超长评论**：截断至模型上下文大小，并添加“（截断）”标记。

#### 监控指标
- **准确率**：与人工标注对比，目标>0.9。
- **输出合规率**：有效JSON输出的比例，目标>0.95。
- **平均延迟**：端到端推理时间，目标<2秒。
- **重试率**：因格式错误重试的比例，目标<0.1。

#### 方案取舍
- **零样本 vs 少样本**：零样本简洁但准确率较低；少样本需维护示例库，增加prompt长度和成本。
- **严格格式 vs 自由格式**：严格格式便于解析但约束模型；自由格式灵活但后处理复杂。
- **角色设定**：角色能提升专业性，但可能引入角色偏差（如过度自信）。
- **温度与top_p**：低温度适合确定性任务，但可能降低多样性。
