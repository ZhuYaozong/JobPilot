# LangGraph 子图与模块化设计

## 概念

在 LangGraph 中，子图（Subgraph）是一种将复杂图结构拆分为独立、可复用的子模块的机制。模块化设计是指将大型图分解为多个功能内聚的子图，每个子图负责特定的任务或逻辑单元。子图可以包含自己的节点、边和状态，并作为父图中的一个节点被调用。这种设计模式支持将工作流分层组织，降低整体复杂度，提升代码的可维护性和可测试性。

## 原理

子图的实现基于 LangGraph 的图编译和状态管理机制。每个子图是一个完整的图实例，拥有独立的 State 和节点执行逻辑。父图在节点中通过 `call_subgraph` 或类似接口调用子图，子图执行完成后将结果返回给父图。子图与父图之间通过状态传递进行通信：父图可以传递输入状态给子图，子图输出状态合并回父图。

关键原理包括：
- **状态隔离**：子图内部的状态变更不影响父图的其他部分，除非显式传递。
- **可组合性**：子图可以嵌套，形成多级模块化结构。
- **复用性**：相同功能的子图可以在不同父图中重复使用。
- **编译优化**：LangGraph 编译器对子图进行独立编译，并在运行时按需执行。

## 实践案例

### 架构流程
假设我们构建一个智能客服工作流，包含“意图识别”、“情感分析”和“响应生成”三个阶段。其中“意图识别”和“情感分析”各自需要调用外部 NLP 服务，逻辑复杂，因此分别封装为子图。

架构流程：
1. 用户输入 -> 父图入口节点（预处理）
2. 预处理后，父图并行调用“意图识别子图”和“情感分析子图”。
3. 两个子图分别处理并返回结果到父图。
4. 父图将结果合并，输入“响应生成”节点，最终输出回答。

### 关键参数
- `intent_subgraph`：包含 `node_classify`（使用预训练模型）和 `node_validate`（置信度检查）。
  - `model_name: "bert-intent-classifier"`
  - `temperature: 0.1`
  - `confidence_threshold: 0.7`
- `sentiment_subgraph`：包含 `node_sentiment`（调用外部 API）。
  - `api_endpoint: "https://api.example.com/sentiment"`
  - `timeout_seconds: 5`
- 父图入口节点：`input_preprocess`（清洗文本，max_length=512）。
- 响应生成节点：`response_generator` 使用 `gpt-4`，`temperature=0.3`。

### 异常处理
- **子图调用超时**：父图设置 `timeout_seconds=10`，超时后返回默认状态（例如 `intent="unknown"`，`sentiment="neutral"`）。
- **子图内部错误**：每个子图节点添加 try-except，捕获异常后将错误信息写入子图状态中的 `error` 字段，父图检查该字段并执行降级逻辑。
- **状态不兼容**：子图与父图状态接口必须匹配，使用 Pydantic 模型校验，类型不匹配时抛出 `ValidationError`，由父图捕获并重试。

### 监控指标
- **子图执行时间**：记录每个子图的开始和结束时间，计算耗时，阈值 3s 报警。
- **子图调用次数**：统计每个子图被调用的总次数，用于分析热点。
- **错误率**：子图内部异常次数 / 总调用次数，超过 5% 触发告警。
- **输出置信度分布**：记录意图识别和情感分析的置信度均值、标准差。

### 方案取舍
- **使用子图 vs 扁平图**：子图增加了调用开销和编译复杂度，但显著提升了可读性和可测试性。适用于逻辑复杂、需要复用的场景；对于简单线性流程，扁平图更高效。
- **并行子图 vs 串行**：本例采用并行调用以降低延迟，但需注意状态合并的复杂度。若子图顺序依赖，应串行执行。
- **子图深度**：建议嵌套不超过 3 层，否则调试困难。可通过单元测试每个子图来保证质量。
