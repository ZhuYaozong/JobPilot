# LangGraph 条件边与路由

## 概念

在 LangGraph 中，条件边（Conditional Edge）是一种根据节点输出动态选择下一个执行节点的机制。与普通边固定连接不同，条件边允许图在执行时根据当前状态或返回结果进行分支跳转，从而实现灵活的工作流路由。条件边通常与“路由函数”配合，该函数接收节点的输出或图状态，并返回目标节点的名称。这种模式常用于实现多步决策、异常处理、用户意图分流等场景。

## 原理

LangGraph 的图由节点（Node）和边（Edge）组成。节点是带有输入输出模式的函数，边定义执行顺序。条件边通过 `add_conditional_edges` 方法添加到图中，其核心参数包括源节点、路由函数以及目标节点映射。路由函数接收图的状态或节点的输出，返回一个字符串键，该键对应一个目标节点名称。若返回 `END` 可终止流程。条件边的执行发生在源节点输出之后，框架自动调用路由函数并跳转。支持多个条件边共存，但需注意路由函数应幂等且无副作用。

## 实践案例

### 架构流程

假设构建一个智能客服工作流：用户查询首先进入“意图识别”节点，根据识别结果路由到“天气查询”、“订单查询”或“转人工”。流程如下：
1. 初始节点 `receive_query` 获取用户输入并存入状态。
2. 意图识别节点 `intent_classifier` 分析查询，输出意图标签（如 `weather`、`order`、`human`）。
3. 条件边根据意图标签路由：`weather` → `weather_handler`，`order` → `order_handler`，`human` → `human_agent`。
4. 各处理器节点返回响应，最终汇聚到 `send_response` 节点输出给用户。

### 关键参数

- **source_node**: 条件边起始节点名称（如 `intent_classifier`）。
- **routing_function**: 接受 `state: State` 参数，返回节点名称字符串。函数内可读取 `state['intent']` 等字段。
- **path_map**: 字典，键为路由函数可能的返回值，值为目标节点名。也可用 `partial` 设置默认路由。
- **optional**: 可选的 `condition` 参数，用于预检查是否启用该条件边。

### 异常处理

当路由函数返回未在 `path_map` 中定义的键时，LangGraph 默认抛出 `ValueError`。为避免中断，可在 `path_map` 中添加一个 `default` 键作为回退节点（如 `fallback_handler`），或让路由函数始终返回存在的键。此外，路由函数内部应捕获异常并返回兜底节点。

### 监控指标

- **路由命中率**：统计各目标节点的执行次数占比，用于发现意图分布变化。
- **路由函数执行耗时**：若路由逻辑复杂（如调用外部模型），需监控延迟。
- **异常路由次数**：记录因无效键或函数异常导致的失败次数。
- **图完成时间**：从开始到结束的总时长，受路由分支影响。

### 方案取舍

- **条件边 vs 节点内分支**：条件边将路由逻辑显式化在图中，便于可视化与维护；若分支逻辑简单且不需要跨节点，可在节点内用 `if-else` 实现。
- **单条件 vs 多条件边**：单条件边清晰；多条件边可用于同时根据多个状态维度路由，但增加复杂度，通常一个条件边足以胜任。
- **静态路由 vs 动态路由**：条件边适合编译时已知的分支；若路由规则运行时动态生成，可考虑用“选择节点”模式——在节点输出中指定下一个节点，但会牺牲图的预测性。

实际应用中，建议将路由函数设计为轻量、纯函数，并充分测试边界情况。
