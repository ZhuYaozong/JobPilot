# Rerank重排技术详解

## 概念

Rerank重排是信息检索和RAG系统中的关键环节，位于初步检索之后、生成回答之前。其目标是对检索阶段返回的候选文档列表进行精细化的相关性排序，从而将最相关的文档置于前列，提升最终生成结果的质量。与粗排（如基于BM25或向量相似度的快速筛选）不同，重排通常采用更复杂但更精确的模型（如交叉编码器），对查询和每篇文档进行深度交互计算，捕捉语义层面的相关性。重排阶段通常处理相对较少的候选文档（如10~100条），以平衡精度与效率。

## 原理

重排的核心原理是利用深度神经网络对查询-文档对进行交互式建模。常用架构包括基于Transformer的交叉编码器（Cross-Encoder），它将查询和文档拼接为一个序列，通过自注意力机制计算两者之间的匹配度，输出一个相关性分数。与双编码器（Bi-Encoder）不同，交叉编码器允许查询和文档词元之间直接交互，因此能更准确地捕捉细粒度语义关系。训练时，通常使用有标注的相关性数据（如人工标注或点击日志）作为监督信号，优化排序损失（如ListNet、LambdaRank）。推理时，对每个候选文档独立计算分数，然后按分数降序排列。此外，也可使用基于列表的排序模型（如SetRank），但实践中交叉编码器最为常见。

## 实践案例

假设我们要构建一个企业知识库RAG系统，使用Elasticsearch进行初步检索，返回top-30文档，然后使用重排模型精排后取top-5送入LLM生成答案。

### 架构流程

1. 用户输入查询Q。
2. Elasticsearch根据BM25和向量混合检索，返回30篇候选文档列表D_candidates。
3. 重排服务加载预训练的交叉编码器模型（如BGE-Reranker-v2-m3）。
4. 将Q与每篇文档d拼接为“[CLS] Q [SEP] d [SEP]”形式，输入模型得到相关性分数s。
5. 按s降序排列文档，取前5篇作为最终上下文。
6. 将上下文与Q送入LLM生成回答。

### 关键参数

- **候选数**：top_k_retrieval = 30，top_k_rerank = 5。候选数过大增加重排延迟，过小可能漏掉相关文档。
- **模型选择**：选择轻量级交叉编码器（如MiniLM-L6）以平衡速度与精度。
- **批处理大小**：batch_size = 16（取决于GPU显存），通过批量推理提高吞吐。
- **得分归一化**：对模型输出分数进行softmax或温度缩放，便于与其他分数融合。

### 异常处理

- **模型超时**：设置推理超时（如200ms/文档），超时后跳过该文档或返回默认低分。
- **输入过长**：若查询+文档超过模型最大长度（如512 token），采用截断策略：优先保留查询和文档首部。
- **空结果**：重排后若所有文档分数低于阈值（如0.1），则返回空列表，触发“无相关知识”提示。
- **模型加载失败**：降级为使用粗排结果，返回原始检索顺序。

### 监控指标

- **重排延迟**：p50/p99重排耗时，阈值应低于查询总时间预算（如500ms）。
- **召回率@5**：重排后top-5中相关文档的比例（需要人工标注或隐式反馈）。
- **分数分布**：监控重排分数均值与方差，异常波动可能表明模型或数据漂移。
- **系统吞吐**：重排服务QPS，确保能支撑峰值请求。

### 方案取舍

- **优势**：重排显著提升排序精度，减少噪声，尤其适用于语义匹配敏感的场景（如问答、对话系统）。
- **代价**：增加推理延迟和计算成本，需权衡效果与性能。若系统对延迟要求极高（如实时搜索），可考虑省略重排或使用更轻量的模型。
- **替代方案**：使用双编码器的内积分数直接排序，或采用基于规则的关键词加权，但精度通常低于交叉编码器重排。
- **混合策略**：在低峰期启用重排，高峰期降级为粗排，或根据查询类型（如长尾查询）动态决定是否重排。
