# LLM幻觉与不确定性管理

## 概念

LLM幻觉是指模型生成的内容看似合理但实际不正确或与事实不符的现象。不确定性则指模型对其输出缺乏置信度，可能源于训练数据偏差、推理时的随机性或者知识边界。幻觉和不确定性密切相关：高不确定性往往伴随幻觉风险。管理幻觉与不确定性旨在提高LLM输出的可靠性和可信度。

## 原理

幻觉的产生主要源于：训练数据中的错误或噪声、模型泛化时的“捏造”行为、以及解码策略（如采样温度）带来的随机性。不确定性分为认知不确定性（epistemic，因知识不足）和偶然不确定性（aleatoric，因随机性）。通过校准输出概率、集成方法、检索增强生成（RAG）等方式可以降低幻觉风险。常见技术包括：对生成内容进行事实核查、使用自信度评分、限制输出范围、以及引入外部知识库。

## 实践案例

### 架构流程

为降低LLM幻觉，我们设计一个包含不确定检测与知识回溯的系统：
1. 用户查询经输入清洗后传给LLM。
2. LLM生成初始回答并附带词语级置信度。
3. 不确定性评估模块分析置信度分布：若整体置信度低于阈值（如0.7），或存在低概率片段，则触发知识检索。
4. 检索模块使用查询和低置信度片段从向量数据库中检索相关文档片段（例如使用embedding相似度）。
5. 融合模块将检索到的证据与原始输出结合，通过重写或修正生成最终回答。
6. 输出后处理：对最终回答进行格式化和事实一致性检验。

### 关键参数

- `temperature`: 采样温度，控制随机性。通常设为0.1-0.5以减少幻觉。
- `top_p`: 核采样概率，建议0.9。
- `confidence_threshold`: 触发知识检索的单词级置信度阈值，设为0.6-0.8。
- `retrieval_k`: 检索文档片段数量，设为3-5。
- `max_retries`: 最多重写次数，设为2。

### 异常处理

- 若检索无结果，则保留原始输出并附加不确定性提示（如“此回答可能不完整”）。
- 若融合模块多次重写仍无法通过一致性校验，则回退到否定回答（如“无法确认”）。
- 监控LLM的响应时间，若超时则返回实时生成的临时回答。

### 监控指标

- **幻觉率**：通过人工评估或自动比对事实数据库计算生成内容中事实错误的比例。
- **不确定性召回**：触发知识检索的查询中实际包含幻觉的比例。
- **平均置信度**：所有输出单词置信度的均值。
- **检索命中率**：检索模块成功返回相关文档的比例。
- **用户反馈评分**：通过点赞/点踩收集。

### 方案取舍

- **优势**：显著降低重要场景下的幻觉，提高可信度。
- **劣势**：增加延迟和计算开销；对知识库覆盖要求高；可能过度谨慎，拒绝正确回答。
- **权衡**：根据业务风险调整置信度阈值：高风险场景（如医疗）用较低阈值，低风险场景允许更高幻觉率以换取流畅性。
