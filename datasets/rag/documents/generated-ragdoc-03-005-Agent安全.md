# Agent安全

## 概念
Agent安全是确保AI Agent在运行过程中不被恶意利用、数据不泄露、行为符合预期的一系列技术与流程。它涵盖身份认证、权限控制、输入输出过滤、数据加密、审计日志等方面。Agent安全的核心目标是防止攻击者通过操纵Agent的输入、输出或内部状态来窃取信息、执行未授权操作或破坏系统完整性。在任务型Agent（如JobPilot）中，Agent需要与外部系统交互（如API、数据库、文件系统），因此必须建立多层次安全防线。

## 原理
Agent安全基于最小权限原则、纵深防御和可信计算基。最小权限原则要求Agent只获得完成其任务所必需的最小权限集，例如仅读取特定数据源而不具备写入能力。纵深防御通过多道安全关卡（如网络隔离、输入验证、运行时沙箱、行为监控）提高攻击成本。可信计算基（TCB）是指确保系统安全所依赖的硬件、软件和固件集合，Agent本身应尽量缩小TCB，避免引入不必要的依赖。实现时，通常在Agent与外部系统之间插入安全代理（Security Proxy）或网关，负责身份验证、请求清洗、速率限制和输出脱敏。此外，使用加密信道（如TLS）保护通信，对敏感数据（如凭据、PII）进行加密存储。运行时监控通过异常检测（如突变的行为模式、异常高频调用）来发现潜在攻击。

## 实践案例
### 架构流程
在JobPilot的Agent安全实践中，设计以下架构：用户请求→安全网关→Agent推理引擎→安全输出过滤器→外部系统。具体流程：1）安全网关验证用户身份（JWT token），并抽取权限标签；2）网关对输入进行SQL注入和XSS过滤；3）Agent接收已清洗的输入，调用规划模块；4）Agent执行工具调用时，通过授权检查（如白名单API端点）；5）返回结果经过输出过滤器，脱敏敏感字段（如身份证号、密码）；6）审计日志记录所有请求和响应摘要。

### 关键参数
- 最大输入长度：5000字符，防止缓冲区溢出
- 速率限制：每个用户每小时1000次请求，基于滑动窗口算法
- 工具白名单：仅允许`/api/read/jobs`和`/api/search/skills`，禁止写操作
- 输出脱敏正则：`(?<=\d{4})\d{10}(?=\d{4})` 用于隐藏电话号码中段
- 加密算法：AES-256-GCM加密静态敏感数据，TLS 1.3用于传输
- 审计日志保留：90天

### 异常处理
- 输入验证失败：返回400并记录“input_violation”告警，不调用Agent
- 授权失败：返回403，触发安全事件，通知管理员
- 输出脱敏异常（如正则错误）：不返回原始数据，改用“脱敏失败，请联系管理员”并记录错误
- Agent超时：设置30秒超时，超时则终止任务并写入失效票据
- 工具调用异常：重试2次，间隔1秒，若仍失败则上报异常并回滚事务

### 监控指标
- 认证失败率：超过5%触发告警
- 输入注入尝试次数：每分钟检测到超过10次，提升安全等级
- 输出脱敏替换率：替换次数/总输出字段数，若低于95%则检查规则
- API调用延迟：P99应小于500ms，超过则扩容安全网关
- 审计日志写入成功率：目标100%，低于99.9%需排查存储

### 方案取舍
- 选择网关模式而非嵌入式安全库：便于统一升级和监控，但增加网络延迟（约10ms）
- 选用正则脱敏而非机器学习：降低误报和计算开销，但无法处理上下文相关的敏感信息（如虚构名字）
- 拒绝自然语言输出禁令（如“不要泄露密码”），转向基于规则的过滤器，因为LLM可能被绕过
- 不主动扫描Agent内部状态（如心智模型），仅审计输入输出，以保护用户隐私
