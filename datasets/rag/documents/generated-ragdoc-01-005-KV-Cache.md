# Transformer 推理优化：KV Cache 机制详解

## 概念

KV Cache 是 Transformer 模型在自回归生成任务中用于加速推理的关键技术。在逐 token 生成时，每个新 token 的注意力计算需要参考之前所有 token 的 Key 和 Value 向量。如果每次重新计算整个序列的 K 和 V，复杂度会随序列长度二次增长。KV Cache 将历史 token 的 Key 和 Value 矩阵缓存起来，避免重复计算，将解码时间复杂度从 O(n^2) 降至 O(n)，显著提升生成速度。

## 原理

在 Transformer 的注意力机制中，对于输入序列，计算 Query (Q)、Key (K)、Value (V) 矩阵。自回归解码时，初始 prompt 的 K 和 V 一次性计算并缓存。每生成一个新 token，仅计算该 token 的 Q、K、V，并将新 K、V 追加到缓存中。注意力计算时，Q 与缓存中所有 K 做点积，再与缓存中所有 V 加权求和。由于缓存维度可动态增长，需要管理显存分配以避免频繁扩容。

## 实践案例

### 架构流程

以一个基于 GPT 的文本生成服务为例：
1. 接收用户输入 prompt，通过 Embedding 和 Transformer 层计算初始 K、V。
2. 将每层 K、V 存入预分配的连续显存块（如 PyTorch tensor 的 `expand` 或 `cat` 操作）。
3. 进入解码循环：对当前 token 计算 Q、K、V，更新缓存，执行注意力，输出下一个 token logits。
4. 循环直到生成终止条件（最大长度或 EOS）。

### 关键参数

- **缓存大小**：由 `max_seq_len` 和 `num_layers` 决定，每个缓存条目形状为 `[batch, num_heads, seq_len, head_dim]`。
- **预分配策略**：按 `max_seq_len` 一次性分配显存，避免动态增长开销。
- **数据类型**：通常使用 float16 或 bfloat16 以节省显存。
- **分页注意力**（如 vLLM 的 PagedAttention）将缓存分块管理，减少内部碎片。

### 异常处理

- **显存不足**：当序列长度超过预分配缓存时，触发 OOM。方案：启用动态扩容或设置最大长度限制，并提示用户截断。
- **缓存未初始化**：首次调用时若未预分配，应自动初始化。
- **并发请求**：每个请求有独立的缓存，避免数据交叉污染。

### 监控指标

- **缓存命中率**：实际使用缓存 token 数与总生成 token 数之比。理想为 1（全部命中）。
- **生成延迟**：计算每 token 平均时间，对比无缓存时的提升倍数。
- **显存占用**：监控缓存占用的显存比例，避免超限。
- **缓存复用频率**：相同 prompt 的缓存可被不同请求重用，提升吞吐。

### 方案取舍

- **静态预分配 vs 动态增长**：静态预分配简单无碎片，但浪费显存；动态节省显存但需处理重分配开销。
- **全精度 vs 量化**：缓存使用 float16 或 int8 量化可减少显存，可能带来轻微精度损失。
- **连续缓存 vs 分页缓存**：连续缓存访问高效，但导致显存碎片；分页缓存更灵活，但需要地址映射。
- **共享 prompt 缓存**：对于相同前缀的请求，共享缓存可减少计算，但需考虑并发安全。
