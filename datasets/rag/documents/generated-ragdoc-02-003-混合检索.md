# 混合检索在RAG中的应用

## 概念

混合检索（Hybrid Search）是RAG系统中结合稀疏检索（如BM25）与稠密检索（如向量嵌入）的检索策略。稀疏检索基于关键词匹配，高效捕捉精确匹配和术语；稠密检索基于语义相似度，能理解上下文和同义表达。混合检索通过融合两者结果，提高召回的准确率与召回率，尤其适用于文档类型多样、查询意图复杂的场景。在RAG流水线中，混合检索通常作为检索阶段的核心组件，为生成模型提供高质量的相关片段。

## 原理

混合检索的核心是融合两种检索方式的分数或排序结果。首先，用户查询分别送入稀疏检索系统（如基于倒排索引的BM25）和稠密检索系统（如基于向量数据库的嵌入相似度搜索）。稀疏检索输出文档与查询的关键词匹配得分；稠密检索输出文档与查询的语义相似度得分。随后，通过归一化（如Min-Max或Z-score）将得分映射到同一量纲，再采用加权求和（权重可调，如0.5:0.5）或重排序（如RRF，Reciprocal Rank Fusion）得到最终排序。RRF的公式为：score = Σ 1/(k + position)，其中k为常数（常用60），position为文档在单检索方式中的排名。融合后取Top-K文档作为检索结果。混合检索平衡了精确匹配与语义理解，降低了单一方式的失败风险。

## 实践案例

### 架构流程

1. **索引构建**：对文档库同时建立BM25倒排索引和稠密向量索引（使用开源嵌入模型如bge-small-zh-v1.5）。
2. **查询处理**：用户查询输入后，同时触发稀疏检索（Elasticsearch BM25）和稠密检索（FAISS向量搜索）。
3. **分数融合**：分别对BM25得分和向量余弦相似度进行Min-Max归一化，然后按权重0.4（BM25）:0.6（稠密）线性加权，再按加权分数降序取Top 20。
4. **下游生成**：将检索文档块送入LLM（如GPT-3.5-turbo）进行回答生成。

### 关键参数

- BM25参数：k1=1.2，b=0.75（控制词频饱和与文档长度归一化）。
- 稠密检索：embedding维度为768，相似度度量使用余弦相似度。
- 融合权重：α（稀疏）和β（稠密）满足α+β=1，案例中α=0.4，β=0.6。
- RRF常数k：默认60，可调。
- 最终返回文档数：Top-K=10。

### 异常处理

- **检索超时**：为稀疏和稠密检索分别设置超时时间（如500ms），若一方超时，则只用另一方的结果，并记录日志告警。
- **向量索引未命中**：若稠密检索因embedding模型更新导致向量维度不匹配，则降级为仅使用稀疏检索，并触发索引重建任务。
- **分数异常**：当归一化后分数全部为0（如查询为空或索引为空），返回默认业务兜底文档，并发出警告。

### 监控指标

- **检索延迟**：稀疏（P99≤200ms）、稠密（P99≤300ms）、融合（≤50ms）。
- **召回率**：在标注数据集上计算Top-10命中标注文档的比例，目标≥90%。
- **响应时间**：RAG整体端到端延迟P95≤2s。
- **空结果率**：无任何检索结果返回的比例，目标<1%。

### 方案取舍

- **优势**：相比单一检索，混合检索在长尾查询（如缩写、拼写错误）上表现更好，避免漏召回。
- **劣势**：增加系统复杂度和维护成本，需要同时维护两种索引，且融合权重需经验调参。
- **适用场景**：文档中既有专业术语又有自然语言描述的场景（如法律、医疗、技术文档）。
- **替代方案**：如果查询高度偏向关键词，可仅用BM25；如果查询语义明确，可仅用稠密检索。混合检索是通用平衡方案。
